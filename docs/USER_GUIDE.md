# 受注・仕入 業務管理システム ご利用ガイド

対象：本システムを初めてご覧になる方、および営業デモを実施される方

---

## 1. はじめに

本システムは、**社内にIT部門を持たない中小企業（SME）様**向けに、「売る」（受注）と「買う」（仕入れ）の両方の業務フローをデジタル化し、AIの力で日々の業務を支援するプラットフォームです。これまで紙の注文書・FAX・手書きメモ・Excelで個別に管理されていた情報を一元化し、経営判断に必要な情報までリアルタイムで把握できるようにします。

本システムは2つの業務フローで構成されています。

**受注業務フロー（売る）**
```
受注 → データ化 → AI照合 → 請求書作成 → 売上分析 → 経営判断
```

| ステップ | 内容 |
|---|---|
| 受注 | お客様からの注文を受け付け、システムに登録する |
| データ化 | 紙の注文書・写真・PDFをAIが読み取り、データとして自動入力する |
| AI照合 | 在庫数量・生産能力と受注内容をAIが照合し、リスクを判定する |
| 請求書作成 | 確定した受注から請求書（PDF）を自動生成する |
| 売上分析 | 受注・売上・請求状況をダッシュボードで可視化する |
| 経営判断 | AIが集計データを分析し、経営者向けのコメントを生成する |

**仕入業務フロー（買う）**
```
仕入先管理 → 発注 → 入荷（在庫が増える） → 仕入請求書・三者照合
```

| ステップ | 内容 |
|---|---|
| 仕入先管理 | 仕入先企業の情報・支払条件を登録・管理する |
| 発注 | 仕入先へ発注し、システムに登録する（AIによる先回り提案も可能） |
| 入荷 | 届いた商品を検収し、在庫数量に反映する |
| 仕入請求書 | 仕入先から届いた請求書を記録し、発注・入荷内容と自動で突き合わせる（三者照合） |

2つのフローは在庫（商品マスタ）でつながっています。**仕入れて入荷した分だけ在庫が増え、その在庫が受注側のAI照合の判断材料になります。** 売り買い両方の業務を1つのシステムで一元管理できる点が、本システムの大きな強みです。

各ステップにAIが組み込まれており、入力の手間とヒューマンエラーを減らしながら、経営者がいつでも最新の状況を把握できるように設計されています。

## 2. AIでできること

本システムの一番の特長は、業務フローの各所にAIが組み込まれていることです。難しい操作は一切不要で、**写真を撮る・確認する・話しかける**だけで、これまで人手に頼っていた作業をAIが肩代わりします。

### 受注業務側

**① データ化 — 写真1枚で入力完了**
**これまで**：届いた注文書を見ながら、取引先名・商品名・数量を1件ずつ手入力していました。
**これから**：注文書の写真やスキャンPDFをアップロードするだけで、AIが内容を読み取り、フォームに自動入力します。読み取りに自信がない項目だけ黄色でハイライトされるので、そこだけ確認すればOKです。

**② AI照合 — 在庫不足を自動で見抜き、理由まで説明**
**これまで**：受注のたびに在庫表とにらめっこし、経験と勘で「これは危ないかも」と判断していました。
**これから**：受注を登録すると、AIが在庫数量と生産能力を自動で照合し、リスクを判定します。しかも「足りません」で終わらせず、なぜ足りないのか・いつまでに何個生産すれば間に合うのかまで、日本語の文章で説明してくれます（例：「精密ギアA-100は在庫8個に対し受注50個、1日の生産能力3個では納期までに不足する可能性があります」）。

**③ 経営判断 — AIが数字を読んで経営コメントを自動生成**
**これまで**：ダッシュボードの数字を見ても、そこから何を読み取るべきかは担当者の経験次第でした。
**これから**：経営ダッシュボードを開くだけで、AIがその時点の受注・売上・請求データを読み取り、「今月は受注が好調だが請求済みの割合が低い」「特定の取引先への依存度が高い」といった経営コメントをその場で自動生成します。

**④ AIチャット — 聞くだけでデータを教えてくれる**
**これまで**：知りたい数字があるたびに、画面を切り替えて検索・集計していました。
**これから**：「在庫が少ない商品はどれですか？」「さくら商事の受注状況と関連在庫を教えてください」と日本語で話しかけるだけで、AIが受注・在庫・請求・売上のデータを自動的に横断して調べ、具体的な数字を含めて答えてくれます。

### 仕入業務側

**⑤ 発注提案 — 頼まれる前にAIが先回りして教えてくれる**
**これまで**：在庫表を定期的にチェックし、「そろそろ発注しないと」と気づくのは担当者の経験と記憶頼みでした。気づいたときには手遅れ、ということも珍しくありません。
**これから**：AIが過去の販売実績（直近90日の消費ペース）・季節変動（前年同月比）・仕入先ごとのリードタイム（発注から入荷までの実績日数）を自動計算し、「この商品はあと◯日で在庫切れになるので、今すぐ発注してください」「この商品は余裕があるので計画的に発注すればOKです」と、商品ごとに緊急度を判定して一覧表示します。ボタン1つでAIが具体的な数字を根拠に日本語で理由も説明してくれ、そのまま発注書の下書きも作成できます。**これは「聞かれたら答える」AIではなく、「聞かれる前に気づかせてくれる」AIです。**

**⑥ 見積書・納品書のAI読み取り — 仕入れ側もデータ化を自動化**
**これまで**：仕入先から届く見積書・納品書を見ながら、品目・数量・金額を手入力していました。
**これから**：受注側と同じ仕組みで、見積書の写真をアップロードすれば発注データの下書きが、納品書の写真をアップロードすれば入荷データの下書きが自動生成されます。信頼度の低い項目は黄色でハイライトされるため、確認だけで済みます。

**⑦ 三者照合 — 発注・入荷・請求のズレをAIならぬシステムが自動で見張る**
**これまで**：発注書・納品書・請求書をそれぞれ別々に管理し、金額が合っているかは手作業で突き合わせていました。
**これから**：発注ごとに「発注済み → 入荷済み → 請求受領済み → 支払済み」の進捗が一目でわかり、入荷が完了しているのに請求金額が発注金額と合わない場合は自動で警告が表示されます。人が3枚の書類を並べて計算し直す必要がなくなります。

> 7つの機能はすべて実際の画面で動いており、演出やモックアップではありません。詳しい操作手順は「5. デモシナリオ」で紹介します。

## 3. 基本機能

左側のメニュー（サイドバー）から、以下の機能にアクセスできます。

### 顧客情報管理
取引先企業の基本情報（会社名・電話番号・住所など）を登録・検索します。「顧客検索」で既存の取引先を探し、「顧客作成」で新規登録します。

### 受注管理
- **受注検索**：登録済みの受注一覧を確認します。ステータスや取引先で絞り込み検索が可能です。
- **受注登録**：取引先・受注日・希望納期・商品明細を手入力し、新しい受注を作成します。
- **受注アップロード（AI）**：注文書の写真やスキャンPDFをアップロードすると、AIが内容を自動で読み取り、受注データの下書きを作成します（詳しくは「4.4 データ化の信頼度」を参照）。

### 商品・在庫管理
商品マスタ（商品名・在庫数量・1日あたりの生産能力・単価）を登録・管理します。ここで登録した情報が、受注時のAI照合や仕入側の発注提案で参照される基礎データになります。

### 請求書管理
発行済みの請求書一覧を確認し、PDFのダウンロードや「入金済み」へのステータス更新ができます。

### 経営ダッシュボード
受注件数・受注金額・請求済み金額・リスクあり受注件数などを集計表示します。画面上部には、AIが集計データから自動生成する経営コメントが表示されます。

### AIチャット
受注・在庫・請求・売上について、チャット形式でAIに自由に質問できます。日本語で質問するだけで、AIが必要なデータを自動的に調べて回答します。（現バージョンでは受注側のデータが対象で、仕入先・発注データは対象外です。）

### 仕入れ管理
- **仕入先検索/登録**：仕入先企業の基本情報と支払条件（締め日・支払サイト・支払日）を検索・登録します。1画面で検索と新規登録の両方ができます。
- **発注検索/登録**：仕入先への発注を検索・登録します。
- **発注アップロード（AI）**：見積書の写真やPDFをアップロードすると、AIが内容を読み取り、発注データの下書きを作成します。
- **入荷検索/登録**：届いた商品の検収記録（入荷）を検索・登録します。登録すると商品の在庫数量が自動的に加算されます。
- **入荷アップロード（AI）**：納品書の写真やPDFをアップロードすると、AIが内容を読み取り、入荷データの下書きを作成します。
- **発注提案**：AIが在庫状況から発注すべき商品を判定し、緊急度別に一覧表示します。
- **仕入請求書管理**：仕入先から届いた請求書を記録し、発注・入荷内容との突き合わせ（三者照合）状況を確認します。

> **参考**：「案件管理」「書類管理」は、本システムに元々備わっている汎用的な案件管理機能です。受注・仕入業務DXの対象外ですが、既存機能として引き続きご利用いただけます。

## 4. 詳細仕様（ステータスの意味など）

### 4.1 受注ステータス

| ステータス | 意味 | いつ変わるか |
|---|---|---|
| **Confirmed**（確定） | 受注確定済み、通常の状態 | 手入力またはデータ化で受注を登録した際の初期状態 |
| **RiskFlagged**（要確認） | 在庫・生産能力の不足が疑われる | AI照合の結果、明細のいずれかが「不足」と判定されると**自動的に**変更される。問題が解消されると自動的にConfirmedへ戻る |
| **Invoiced**（請求済み） | 請求書発行済み | 「請求書作成」ボタンで請求書を発行すると自動的に変更される |

> Draft（下書き）・Cancelled（キャンセル）というステータスも定義されていますが、現バージョンのUIにはこれらを設定する操作がなく、将来の拡張のために予約されています。

受注詳細画面では、ステータスに応じて操作できる内容が変わります。
- **Confirmed**のとき → 「請求書作成」ボタンが表示される
- **RiskFlagged**のとき → 「請求書作成」ボタンの代わりに「在庫/生産能力の不足が疑われる受注です。請求書を発行する前にご確認ください。」という警告文が表示される
- どちらの状態でも「再照合（AI）」ボタンでAI照合をやり直せる

### 4.2 AI照合 リスクレベル

| 表示 | 内部値 | 色 | 意味 |
|---|---|---|---|
| 在庫十分 | Sufficient | 緑 | 現在の在庫数量だけで受注数量を満たせる |
| 要注意 | Warning | 黄 | 在庫だけでは不足するが、希望納期までの生産能力を加味すれば対応可能 |
| 不足 | Insufficient | 赤 | 在庫と生産能力を合わせても、希望納期までに対応できない可能性が高い |

**判定ロジック**：受注数量をまず「現在庫数量」と比較します。不足する場合は、さらに「現在庫数量＋（希望納期までの残り日数 × 1日あたり生産能力）」と比較します。明細（商品）ごとにこの判定を行い、1件でも「不足」があれば受注全体のステータスがRiskFlaggedになります。在庫数量は、他の未請求の受注ですでに確保（コミット）されている数量を差し引いたうえで判定されるため、複数の受注が同じ商品を取り合うような二重カウントは起きません。

判定結果には、AI（Claude）が生成した**日本語の説明文と推奨アクション**が添えられます。受注詳細画面のリスクチップにマウスを合わせる（ツールチップ表示）と、なぜそのリスクレベルになったのか、次に何をすべきかを確認できます。

### 4.3 請求書ステータス

| ステータス | 意味 | いつ変わるか |
|---|---|---|
| **Issued**（発行済み） | 請求書作成時の初期状態 | 受注から「請求書作成」を実行すると設定される |
| **Paid**（入金済み） | 入金が確認された状態 | 請求書一覧の「入金済みにする」ボタンで手動更新 |

> Draft（下書き）・Overdue（支払期限超過）も定義されていますが、現バージョンでは自動的な期限超過判定はまだ実装されておらず、手動運用が前提です。

### 4.4 データ化の信頼度（confidence）

注文書・見積書・納品書の写真やPDFをアップロードすると、AIが内容を読み取り、各項目を自動入力します。読み取った項目ごとに**信頼度（0〜1の数値）**が付与され、**0.7未満の項目は黄色でハイライト表示**されます。これは「AIがあまり自信を持って読み取れなかった項目」を人の目で確認しやすくするための仕組みです。登録前に必ず内容を確認し、必要に応じて手動で修正してください（登録ボタンを押すまではデータベースに保存されません）。この仕組みは受注アップロード・発注アップロード・入荷アップロードの3か所すべてで共通です。

### 4.5 発注ステータス

| ステータス | 意味 | いつ変わるか |
|---|---|---|
| **Draft**（下書き） | 作成直後、まだ確定していない | 発注登録直後の初期状態 |
| **Confirmed**（確定） | 仕入先へ発注済み | 発注を確定操作すると設定される |
| **PartiallyReceived**（一部入荷） | 発注数量の一部だけ届いた | 入荷登録で明細の一部だけ入荷数量が発注数量に満たない場合 |
| **Received**（入荷完了） | 発注した商品がすべて届いた | すべての明細で入荷数量が発注数量に達すると自動的に変更される |
| **Cancelled**（キャンセル） | 発注取消 | — |

> 受注側の「RiskFlagged」に相当するステータスは発注にはありません。自社の在庫・生産能力という判断材料がある受注と異なり、仕入先側の信頼度を判定する材料がないためです（そのぶん、仕入先の対応力そのものを先読みするのが次の「発注提案」機能です）。入荷が発注数量を上回った場合（誤入荷や多めの納品）は、エラーにはせず警告として扱われます。

### 4.6 仕入請求書ステータス

| ステータス | 意味 | いつ変わるか |
|---|---|---|
| **Recorded**（記録済み） | 仕入請求書を登録した直後の状態 | 仕入請求書登録時の初期状態 |
| **Paid**（支払済み） | 支払いが完了した状態 | 仕入請求書一覧の操作で手動更新 |

支払期限（DueDate）は、仕入先マスタに設定した支払条件（締め日・支払サイト・支払日）から、仕入請求書の登録時に自動計算されます。

### 4.7 三者照合（発注・入荷・請求の突き合わせ）

発注詳細画面には、その発注が今どこまで進んでいるかを示す4つのチェックポイントが常時表示されます。

| チェックポイント | 内容 |
|---|---|
| 発注済み | 仕入先へ発注が確定している（常に表示） |
| 入荷済み（全部／一部） | 発注した数量のうち、実際に入荷した数量の状況 |
| 請求受領済み／請求未受領 | 仕入先から仕入請求書を受け取って記録済みかどうか |
| 支払済み／未払い | 記録した仕入請求書の支払いが完了しているかどうか |

さらに、**入荷が完了しているにもかかわらず、受け取った請求書の合計金額が発注金額と一致しない場合**は、金額不一致の警告が表示されます（入荷が完了する前は、仕入先がまだ全量分を請求していないだけの可能性があるため、あえて警告を出しません）。これにより、担当者が発注書・納品書・請求書を手作業で並べて確認する手間が不要になります。

### 4.8 発注提案のロジック

発注提案画面に表示される緊急度は、次の4段階です。

| 表示 | 意味 |
|---|---|
| 至急発注 | 在庫切れ予測日までに発注が間に合わない可能性がある |
| 計画的発注 | 在庫に余裕はあるが、計画的な発注を推奨する |
| 発注済み・順調 | すでに発注済みで、入荷予定日が在庫切れ予測日より前 |
| データ不足 | 販売実績が少なく、提案を算出できない |

判定に使う数値（1日あたりの消費ペース・在庫切れ予測日・発注期限・提案数量・提案仕入先）は、**過去の販売実績と発注〜入荷の実績データからすべてC#のロジックで計算**しており、AIの推測ではありません。AI（Claude）が担うのは、「至急発注」「計画的発注」に該当する商品について、担当者向けの説明文を日本語で生成する部分のみです。この説明文はAPIコストと生成品質の両方を考慮し、一覧を開いた時点では自動生成されず、**商品ごとに「AIで生成」ボタンを押した分だけ**生成されます。同じ緊急度の商品は最初は共通の定型文（テーブルのグループ見出しに1回だけ表示）で説明され、個別の事情を知りたい商品だけ、担当者が選んでAIに理由を生成させる設計です。

## 5. デモシナリオ（顧客向けデモの進め方）

デモは大きく2部構成です。**Part A（受注業務・売る側）** と **Part B（仕入業務・買う側）** で、それぞれ実際にシステムに登録されているデモデータ（取引先「さくら商事株式会社」、商品「精密ギアA-100」など）を使います。基本操作は簡潔に流し、**AIが関わる「驚きのポイント」を軸に**構成しています。時間が限られる場合はPart Aのみ、または関心の高い側（売る/買う）だけに絞っても構いません。

### Part A：受注業務編（売る）

#### ステップA0：ログイン → 経営ダッシュボード（wow①：AIが経営状況を要約）

ログイン後、まず「経営ダッシュボード」を開きます。

> 口頭説明例：「まず経営者の視点から見てみましょう。受注件数、売上金額、請求状況が一目でわかります。」

画面上部の**AI経営コメントカード**に注目してもらいます。AIが集計データを読み取り、日本語で「今月は受注が急増しているが、請求済みの割合が低い」「特定の取引先・商品への依存度が高い」といった、経営者がすぐに意思決定できるコメントを自動生成しています。

> 口頭説明例：「これは人が作ったコメントではなく、AIがこのダッシュボードの数字をリアルタイムで読んで、その場で生成しています。毎日見るたびに、最新の状況に合わせたコメントが出ます。」

#### ステップA1：受注アップロード（AI）（wow②：写真から受注データを自動生成）

サイドバーから「受注アップロード（AI）」を開きます。手書きの注文書やFAXの写真（サンプル画像）をアップロードします。

> 口頭説明例：「これまでは、届いた注文書を見ながら一つ一つ手入力していたと思います。試しに、この注文書の写真をアップロードしてみます。」

数秒後、取引先名・商品名・数量・単価がすでに入力された状態の画面が表示されます。信頼度が低い項目は黄色でハイライトされているため、そこだけ確認すればよいことを説明します。

> 口頭説明例：「AIが自動で読み取り、フォームに入力しました。黄色になっている部分だけ確認すれば、あとはそのまま登録ボタンを押すだけです。」

#### ステップA2：AI照合とリスク確認（wow③：AIが在庫リスクを判断し理由まで説明）

内容を確認して受注を登録すると、システムが自動的にAI照合を実行します。今回は商品「精密ギアA-100」（在庫8個、1日の生産能力3個）を含む受注のため、ステータスが**RiskFlagged（要確認）**になっていることを見せます。

> 口頭説明例：「登録すると同時に、AIが自動で在庫と生産能力を照合しています。この受注は『要確認』になっていますね。」

受注詳細を開き、リスクチップにマウスを合わせてツールチップを表示します。AIが生成した日本語の説明（「在庫と生産能力を合わせても不足する可能性があります」など）と推奨アクションを見せます。

> 口頭説明例：「単に赤信号を出すだけでなく、なぜ足りないのか、どう対応すべきかまでAIが日本語で説明してくれます。これなら経験の浅い担当者でも判断に迷いません。」

#### ステップA3：請求書作成

在庫に問題のない別の受注（ステータスConfirmed）を開き、「請求書作成」ボタンを押します。PDFをダウンロードし、日本語の請求書がその場で自動生成されることを見せます。

> 口頭説明例：「確定した受注からワンクリックで請求書が作成できます。フォーマットの統一やミスの防止にもつながります。」

#### ステップA4：AIチャット（wow④：自然な会話でデータを横断的に分析）

最後にサイドバーから「AIチャット」を開き、実際に質問を入力します。

- 「在庫が少ない商品はどれですか？」
- 「さくら商事の受注状況と、関連商品の在庫を教えてください」

> 口頭説明例：「最後に、これが一番驚かれる機能です。データベースを検索する必要はありません。知りたいことをそのまま日本語で聞くだけです。」

AIが複数のデータ（受注・在庫）を自動的に横断して調べ、具体的な数字を含めて自然な日本語で回答する様子を見せます。特に、1つの質問から複数の情報源を組み合わせて回答する点（さくら商事の受注状況 **と** 関連商品の在庫、を1回の質問で同時に回答する）を強調します。

> 口頭説明例：「今の質問には、受注データと在庫データの両方が必要でしたが、AIが自動で判断して両方を調べて回答しています。データを探す時間がゼロになります。」

### Part B：仕入業務編（買う）

#### ステップB0：仕入先確認（基本操作、簡潔に）

サイドバーから「仕入先検索/登録」を開き、登録済みの仕入先（会社名・支払条件）を確認します。

> 口頭説明例：「仕入先の情報と、締め日・支払サイトといった支払条件もここでまとめて管理します。検索画面から直接、新規登録もできます。」

#### ステップB1：発注提案（wow⑤：頼まれる前にAIが気づかせてくれる）

サイドバーから「発注提案」を開きます。ページを開いただけではAIは呼ばれておらず、緊急度別（至急発注／計画的発注／発注済み・順調／データ不足）にグループ化された商品一覧が即座に表示されることを説明します。

> 口頭説明例：「これは在庫がある閾値を切ったら知らせる、という単純な仕組みではありません。過去の販売実績・季節変動・仕入先ごとのリードタイムまで計算に入れて、商品ごとに『いつまでに発注すべきか』を判定しています。」

「至急発注」グループの商品で「AIで生成」ボタンを押します。数秒後、具体的な数字（在庫切れまでの日数、1日あたりの消費ペース、リードタイムなど）を根拠にした、説得力のある日本語の理由が表示されます。

> 口頭説明例：「担当者が気づく前に、AIが先回りして『この商品は今すぐ発注しないと欠品します』と教えてくれます。しかもテンプレート文ではなく、この商品固有の数字を根拠にAIが説明しています。ボタンを押した商品だけAIが動くので、無駄なコストもかかりません。」

「発注書を作成」ボタンを押し、提案内容（仕入先・数量）が入った状態で発注書の作成画面が開くことを見せます。

> 口頭説明例：「提案からそのまま発注書の下書きが作れるので、あとは内容を確認して登録するだけです。」

#### ステップB2：発注アップロード（AI）と入荷（在庫が増える瞬間）

サイドバーから「発注アップロード（AI）」を開き、見積書の写真（サンプル画像）をアップロードして、AIが品目・数量・金額を自動で読み取る様子を見せます（受注アップロードと同じ体験であることに軽く触れる程度でOKです）。

発注を確定したあと、「入荷検索/登録」または「入荷アップロード（AI）」から入荷を登録します。登録直前・直後で商品・在庫管理画面の在庫数量を見比べ、**入荷した分だけ在庫数量が実際に増える**ことを見せます。

> 口頭説明例：「入荷を記録すると、在庫数量がその場で加算されます。そしてこの在庫は、さきほどPart Aでご覧いただいた受注側のAI照合でもそのまま使われます。つまり、仕入れて入荷した瞬間から、売る側のリスク判定の精度が上がっていく仕組みです。」（Part Aを実施済みの場合、両パートをつなぐ最大の見せ場です）

#### ステップB3：仕入請求書と三者照合（wow⑥：3枚の書類の突き合わせを自動化）

発注詳細画面を開き、上部に並ぶ「発注済み／入荷済み／請求受領済み／支払済み」のチェックポイント（チップ）を見せます。

> 口頭説明例：「この発注が今どこまで進んでいるか、4つのステップで一目でわかります。」

仕入請求書管理から該当の仕入請求書を登録し、発注詳細画面に戻って「請求受領済み」に変わったことを確認します。もし発注金額と請求金額が一致しない場合は、警告メッセージが自動表示されることを見せます。

> 口頭説明例：「発注書・納品書・請求書の3枚を人が並べて金額を計算し直す必要はありません。入荷が完了した時点で金額が合っているかをシステムが自動でチェックし、ズレがあれば警告してくれます。」
